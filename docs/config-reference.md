# Справочник по конфигу `config/cameras.json`

**Этот файл теперь опционален.** Основной способ настройки — веб-интерфейс:
откройте `http://localhost:3000` → **«Настройки»** → «Добавить камеру» /
«Раскладка» / «Защита». UI пишет тот же `config/cameras.json` и сам
перезапускает MediaMTX, поэтому ничего не нужно редактировать руками и
перезапускать сервер.

Справочник ниже описывает **advanced-способ**: файл `config/cameras.json`
остаётся для массовой настройки (залить сразу много камер), ручных правок,
переноса стена на другую машину и бэкапа. Если вы просто добавляете пару камер —
делайте это в UI.

Рабочий конфиг видеостена — это файл `config/cameras.json`. Он **не коммитится**
(см. `.gitignore`), поэтому в репозитории лежит только пример:
`config/cameras.example.json`.

Начало работы (advanced-путь, если вы правите файл, а не UI):

```bash
cp config/cameras.example.json config/cameras.json
# отредактируйте host / username / password под свои камеры
```

Конфиг — обычный JSON. Если файл не найден, не парсится или не проходит проверку,
сервер всё равно поднимется: он пишет причину в лог и отдаёт **пустой список
камер** (чтобы UI оставался доступен), поэтому после правок полезно проверять файл:

```bash
node -e "JSON.parse(require('fs').readFileSync('config/cameras.json','utf8')); console.log('valid')"
```

## Поля

### Корень

| Поле | Тип | Обязательное | По умолчанию | Описание |
| --- | --- | --- | --- | --- |
| `httpPort` | number | нет | `3000` | Порт веб-интерфейса. Используется, только если не задана переменная окружения `PORT` — она имеет приоритет. |
| `mediamtx` | object | нет | см. ниже | Настройки локального сервера MediaMTX, который отдаёт HLS и статусы потоков. |
| `cameras` | array&lt;object&gt; | нет | `[]` | Список камер. Порядок элементов задаёт порядок плиток в UI. Пустой список — валидный конфиг (UI покажет «Нет камер»). |
| `auth` | object | нет | — | Токен доступа к API редактирования (см. ниже). |

### `auth`

| Поле | Тип | Обязательное | По умолчанию | Описание |
| --- | --- | --- | --- | --- |
| `token` | string | нет | — (нет) | Токен доступа для редактирования через API. Пока поле отсутствует или пустое, `GET`/`PUT /api/config` открыты (обычный режим для домашней LAN). Если токен задан, эти запросы обязаны нести заголовок `x-tapo-token: <token>`, иначе сервер отвечает `401`. Отключить защиту — убрать поле или очистить токен. В UI задаётся в «Настройки → Защита». Это защита от случайных правок, **не** полноценная аутентификация: просмотр камер и сам UI остаются открытыми. |

### `mediamtx`

| Поле | Тип | Обязательное | По умолчанию | Описание |
| --- | --- | --- | --- | --- |
| `hlsAddress` | string | нет | `":8888"` | Адрес, на котором MediaMTX слушает HLS. Порт из этого поля используется браузером для воспроизведения (`:8888` = все интерфейсы, порт 8888). |
| `apiAddress` | string | нет | `":9997"` | Адрес HTTP API MediaMTX. Через него сервер опрашивает состояние потоков и показывает статусы (онлайн/офлайн). В браузер не отдаётся. |
| `webrtcAddress` | string | нет | `":8889"` | Адрес, на котором MediaMTX слушает WebRTC/WHEP. Если поле не задано, используется стандартный `:8889`; на этот же порт указывают WHEP-адреса в API. |

### `cameras[]`

| Поле | Тип | Обязательное | По умолчанию | Описание |
| --- | --- | --- | --- | --- |
| `id` | string | да | — | Уникальный идентификатор камеры: латиница и дефисы (`office-front`). Используется в URL-ах и в именах потоков MediaMTX, поэтому менять его после настройки нежелательно. |
| `name` | string | да | — | Подпись камеры в UI. Произвольный текст, можно кириллицей. |
| `host` | string | да | — | IP-адрес камеры в локальной сети (например `192.168.1.101`). |
| `port` | number | да | — | Порт RTSP (число). У камер Tapo это стандартный `554`, но указать его нужно явно. |
| `username` | string | да | — | Логин RTSP-аккаунта. Это **не** аккаунт TP-Link из мобильного приложения, а отдельный «Camera Account», который создаётся в приложении Tapo: *Настройки камеры → Дополнительно → Учётная запись камеры*. |
| `password` | string | да | — | Пароль RTSP-аккаунта («Camera Account»). Никогда не попадает в браузер — см. примечание ниже. |
| `streams` | object | да | — | Пути потоков на камере. |
| `streams.hd` | string | да | — | Путь основного потока (высокое качество). У Tapo — `/stream1`. Используется в крупной плитке. |
| `streams.preview` | string | да | — | Путь потока превью (низкое качество/битрейт). У Tapo — `/stream2`. Используется для мелких плиток и экономит ресурсы. |
| `layout` | object | нет | `{ "x": 0, "y": 0, "w": 320, "h": 180, "rotation": 0, "scale": 1 }` | Положение и размер плитки на свободном холсте: `x`/`y` — смещение в CSS-пикселях, `w`/`h` — размер (не меньше 160×90), `rotation` — поворот в градусах (нормализуется в 0…359), `scale` — масштаб (0.25…4). Любое подполе можно опустить — недостающие берутся из значения по умолчанию. Обычно задаётся перетаскиванием в режиме «Раскладка», вручную — только для массовой настройки. |

## Пример заполнения

```json
{
  "httpPort": 3000,
  "mediamtx": { "hlsAddress": ":8888", "apiAddress": ":9997" },
  "cameras": [
    {
      "id": "office-front",
      "name": "Офис — вход",
      "host": "192.168.1.101",
      "port": 554,
      "username": "tapo",
      "password": "CHANGE_ME",
      "streams": { "hd": "/stream1", "preview": "/stream2" }
    },
    {
      "id": "office-back",
      "name": "Офис — склад",
      "host": "192.168.1.102",
      "port": 554,
      "username": "tapo",
      "password": "CHANGE_ME",
      "streams": { "hd": "/stream1", "preview": "/stream2" }
    }
  ]
}
```

Это ровно то содержимое, что лежит в `config/cameras.example.json`. Скопируйте
его в `config/cameras.json` и подставьте реальные адреса и пароли.

## Пароль никогда не попадает в браузер

`username` и `password` остаются **только на сервере**. Сервер сам формирует RTSP-URL
(`rtsp://user:pass@host:554/stream1`), подключается к камере и публикует поток в
MediaMTX; браузер получает уже готовый HLS без учётных данных. Пароль не
подставляется в HTML, не попадает в клиентский JavaScript, не отдаётся через API
статусов и не должен появляться в логах.

API редактора (`GET /api/config`) — единственное исключение по объёму: ему нужны
`host`, `port`, `username`, пути потоков и раскладка, чтобы форма могла их показать.
Пароля там нет: вместо него отдаётся булев флаг `passwordSet`. Это видно по самому
ответу — ключа `"password"` в нём нет, только `"passwordSet"`:

```bash
curl -s localhost:3000/api/config
```

Практические следствия:

- не публикуйте `config/cameras.json` и скриншоты с ним — файл в `.gitignore` не случайно;
- не добавляйте `password` в ответы API: список камер отдаёт только `id`, `name`, `status`,
  раскладку и адреса MediaMTX, а редактор — `passwordSet` вместо пароля;
- доступ к самому веб-интерфейсу ограничивайте локальной сетью: токен из `auth.token`
  закрывает редактирование, но не просмотр.
