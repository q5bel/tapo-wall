# План: Tapo C310 — локальный просмотр (офис: камеры → Keenetic → Mac)

> Сейчас делаем **локальный MVP**: смотреть камеры офиса в браузере на Mac, на локальном порту,
> как DSH web. Без VPN, без VPS, без внешних серверов. Мульти-сайт и 24/7 — потом, по мере роста.

## Архитектура MVP
```
C310 (офис, за Keenetic) ──RTSP──▶ Mac: MediaMTX (RTSP → HLS/WebRTC) ──▶ Браузер http://localhost:3000
                                        ▲
                                 Node.js (раздаёт UI + /api/cameras) — пишем на JS
```

Почему этого достаточно:
- Mac и камеры в одной сети офиса (оба за Keenetic) → **VPN не нужен**, камеры видны напрямую по RTSP.
- Браузер RTSP не понимает → **MediaMTX** переупаковывает в HLS/WebRTC (готовый бинарник, не пишем).
- **Telegram-алерты работают и с локального Mac** — нужен только интернет (есть), сервер не нужен.

## Стек (всё бесплатно)
- MediaMTX — ретранслятор RTSP → HLS/WebRTC: `brew install mediamtx`.
- Node.js + Express — сервер UI и `/api/cameras` (пишем на JS). Node уже есть.
- Фронтенд — HTML/CSS/JS + плеер `hls.js`.
- Опционально: FFmpeg (есть) — детект движения/скриншоты для алертов.

## Что нужно (чек-лист)
- [ ] В приложении Tapo для каждой C310 включить «Camera Account» (RTSP/ONVIF): Настройки камеры → Дополнительные настройки → Camera Account → логин/пароль.
- [ ] На Keenetic назначить камерам **статические IP** (зарегистрированное устройство → фиксированный адрес).
- [ ] Проверить поток: `ffplay -rtsp_transport tcp "rtsp://логин:пароль@IP:554/stream1"` (или VLC).
- [ ] `brew install mediamtx`.
- [ ] `hls.js` (CDN или файл).

## Фазы MVP
### Фаза 0 — Подготовка камер
- [ ] Camera Account на каждой C310 (логин/пароль для RTSP).
- [ ] Статические IP камер на Keenetic.
- [ ] Проверка потока локально через ffplay/VLC.
- [ ] Записать RTSP-адреса: `stream1` (высокое качество) и `stream2` (превью).

### Фаза 1 — MediaMTX
- [ ] Установить MediaMTX.
- [ ] В `mediamtx.yml` прописать камеры офиса (каждая — RTSP-источник).
- [ ] Запустить, открыть HLS-ссылку в браузере — видео идёт. Проверить WebRTC (WHEP).

### Фаза 2 — Node-сервер (UI + API)
- [ ] `npm init` + Express.
- [ ] Список камер в JSON (имя, IP, stream1/stream2).
- [ ] `GET /api/cameras` (без паролей наружу).
- [ ] Раздача статики (HTML/JS/CSS).
- [ ] Команда запуска одной строкой (например `npm start` → поднимает MediaMTX + сервер).

### Фаза 3 — Фронтенд
- [ ] Грид плиток: по плитке на камеру.
- [ ] Превью через `hls.js` (stream2), клик → полноэкран (stream1).
- [ ] Статусы «онлайн/офлайн/подключение», автореконнект.
- [ ] (Позже) WebRTC для низкой задержки.

### Фаза 4 — Запуск «как dsh web»
- [ ] Один скрипт запуска (`start.sh` / `npm start`): стартует MediaMTX + Node, открывает браузер на `http://localhost:3000`.
- [ ] Пользоваться как DSH web: поднял → открыл порт → смотришь.

### Фаза 5 — Алерты в Telegram (опционально, работает локально)
- [ ] Бот у `@BotFather`, токен, chat_id.
- [ ] Watchdog: «камера офлайн/онлайн» → сообщение.
- [ ] (Опционально) «движение»: ONVIF-события C310 или FFmpeg-детект + скриншот.
- [ ] Команда `/status` — какие камеры онлайн.

## Стоимость MVP
$0 — всё уже есть или бесплатно.

## Ограничения MVP (осознанно)
| Ограничение | Последствие |
|-------------|-------------|
| Только из офисной сети | С дачи/из дома не посмотреть (пока) |
| Mac должен быть включён | Нет Mac → нет просмотра и алертов |
| HLS задержка 2–5 с | Приемлемо; WebRTC как улучшение |
| Камера офлайн / IP сменился | Watchdog-алерт; статический IP на Keenetic |
