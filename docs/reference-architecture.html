Камеры Tapo C310 — локальный просмотр на Mac

Офис: камеры → Keenetic → Mac. Локальный web на порту, как DSH web. Без VPN и серверов.
MVP: MediaMTX + Node.js + hls.js — всё бесплатно

1. Вывод коротко

Делаем локальный web-интерфейс на Mac: ретранслятор MediaMTX тянет RTSP с камер офиса и отдаёт видео в браузер (HLS/WebRTC), а маленький Node.js-сервер раздаёт страницу с сеткой камер. Открываешь http://localhost:3000 — и смотришь. Без VPN, VPS и внешних серверов.

Камеры и Mac — в одной офисной сети (оба за Keenetic), поэтому RTSP-потоки видны напрямую, VPN не нужен. Единственный «не-веб» кусочек — MediaMTX, потому что браузер не умеет играть RTSP. Его берём готовым, а не пишем.

3. Почему сейчас не нужны VPN и сервер

  • Камеры и Mac в одной сети офиса → RTSP виден напрямую, VPN не нужен.
  • Просмотр нужен локально → хостинг/VPS не нужен.
  • Telegram-алерты работают и с локального Mac — Mac шлёт сообщения в Telegram через свой интернет, сервер для этого не требуется.
Всё это «по мере роста» добавится без переписывания: VPN на Keenetic для других точек, VPS для 24/7.

4. Что нужно для старта (чек-лист)

  • RTSP-аккаунт («Camera Account») для каждой камеры — в приложении Tapo: Настройки камеры → Дополнительные настройки → Camera Account → логин/пароль.
  • Статические IP камер на Keenetic (зарегистрированное устройство → фиксированный адрес).
  • MediaMTX — brew install mediamtx (Homebrew уже есть).
  • Node.js — уже есть (v24.21.0).
  • FFmpeg — уже есть (8.1.2), для детекта движения/скриншотов.
  • hls.js — плеер (CDN/файл).

6. Техфакты по Tapo C310

  • Видео: H.264, до 2K (2304×1296), два потока.
  • RTSP-адрес основного потока (высокое качество):
    rtsp://логин:пароль@IP:554/stream1
  • RTSP-адрес низкого качества (для превью-сетки):
    rtsp://логин:пароль@IP:554/stream2
  • Порт RTSP: 554. Порт ONVIF: 2020.
  • RTSP/ONVIF-доступ включается отдельно через «Camera Account» в приложении Tapo.
