# tapo-wall

**Локальный видеостен для RTSP-камер: склонировал → `npm start` → добавил камеры в веб-интерфейсе → смотришь камеры в браузере.** Никакого VPN, VPS, облака и облачной подписки: Node-сервер и MediaMTX работают на вашем компьютере, камеры берутся напрямую по RTSP из локальной сети, а браузер получает уже перепакованный HLS. Целевой пример — камеры TP-Link Tapo за роутером Keenetic, но подойдёт любая камера с RTSP.

Настройка живёт в веб-интерфейсе (`http://localhost:3000` → «Настройки»): добавили камеру, подвинули плитки, сохранили — MediaMTX перезапустился сам. Файл `config/cameras.json` остаётся **опциональным, advanced-способом**: он удобен для массовой настройки, ручных правок и бэкапа, но больше не является обязательным шагом.

![tapo-wall: тёмная сетка камер со статусами](docs/screenshot.png)

## Возможности

- **Живая сетка камер** — адаптивный wall: 1 колонка на телефоне, 2 на планшете, 3 на широком экране. Положение плиток берётся из `cameras[].layout`, а кнопка «Прибрать» раскладывает их ровной сеткой.
- **Настройка из интерфейса** — «Добавить камеру»: host / port / username / password / потоки → «Сохранить». Конфиг пишется в `config/cameras.json`, MediaMTX перезапускается автоматически, перезагрузка страницы не нужна. Пароли по-прежнему не покидают сервер: в браузер уходит только флаг `passwordSet`.
- **Свободная раскладка** — переключатель «Раскладка» включает режим редактирования: плитки можно двигать мышью, растягивать за углы, поворачивать за верхнюю точку и масштабировать; положение сохраняется в конфиг.
- **Опциональный токен доступа** — «Настройки → Защита» задаёт токен: без него API остаётся открытым (обычный режим для домашней LAN), с ним редактирование конфига требует заголовок `x-tapo-token`.
- **Превью + полноэкранный просмотр** — каждая плитка играет лёгкий поток `preview` (`/stream2`), клик по плитке открывает крупный `hd`-поток (`/stream1`) в диалоге.
- **Статусы онлайн / офлайн / подключение** — сервер опрашивает HTTP API MediaMTX (`GET /v3/paths/list`) раз в 5 секунд; состояние показывается бейджем на каждой плитке.
- **Тёмный минимализм на shadcn/ui** — React + Tailwind + компоненты shadcn/ui, только семантические токены темы, без визуального шума.
- **Пароли не уходят в браузер** — `password` остаётся на сервере: он сам формирует `rtsp://…` и публикует поток в MediaMTX. Список камер (`/api/cameras`) отдаёт только `id`, `name`, `status`, раскладку и HLS/WebRTC-адреса локального MediaMTX. Редактор конфига (`/api/config`) добавляет `host`, `port`, `username` и пути потоков, но вместо пароля — только флаг `passwordSet`.
- **Автовосстановление потока** — `hls.js` переподключается с backoff (2 с → 5 с → 10 с), упавшая камера гасит только свою плитку.
- **Одна команда запуска** — `npm start` поднимает MediaMTX и сервер (при необходимости докачивает бинарник и собирает фронтенд).

## Архитектура

```
  ┌──────────────┐        ┌──────────────┐
  │ Tapo C310    │        │ Tapo C310    │   камеры в одной LAN
  │ 192.168.1.101│        │ 192.168.1.102│   с компьютером
  └──────┬───────┘        └──────┬───────┘
         │                       │
         │   RTSP :554           │   RTSP :554
         │   /stream1 (HD)       │
         │   /stream2 (preview)  │
         └───────────┬───────────┘
                     ▼
          ┌─────────────────────┐
          │  MediaMTX           │   rtsp://user:pass@host:554/stream1
          │  (локальный бинарь) │   → пути  office-front_hd
          │  HLS  :8888         │           office-front_preview
          │  API  :9997         │   пароли живут только здесь
          └──────┬───────┬──────┘
                 │       │
       HLS (.m3u8)│      │ HTTP API (статусы, только localhost)
                 │       │
                 ▼       ▼
          ┌────────────────────────────────────────┐
          │  Node-сервер (Express)  :3000          │
          │  • /api/cameras — список без секретов  │
          │  • /api/config  — конфиг без паролей   │
          │  • /api/health  — health-check         │
          │  • раздаёт собранный UI (web/dist)     │
          │  • спавнит MediaMTX и пишет mediamtx.yml│
          └────────────────┬───────────────────────┘
                           │  HTTP
                           ▼
                  ┌──────────────────┐
                  │  Браузер         │   http://localhost:3000
                  │  hls.js + shadcn │   сетка плиток → диалог HD
                  └──────────────────┘
```

Ключевая идея: браузер не знает ни одного пароля и не умеет RTSP. Он получает с `:3000` список камер и HLS-плейлисты с `:8888`. RTSP-источники и учётные данные остаются в процессе Node/MediaMTX.

## Требования

- **Node.js ≥ 20** (проверено на Node 24; нужен встроенный `fetch` для автозагрузки MediaMTX).
- **Камеры и компьютер в одной LAN** — прямой доступ по RTSP, без маршрутизации между подсетями.
- **Доступ камер по RTSP** — включённый RTSP-аккаунт и известные логин/пароль (у Tapo это «Camera Account», см. ниже).
- Свободные локальные порты `3000` (UI/API), `8888` (HLS), `9997` (API MediaMTX).
- Бинарник MediaMTX: `npm start` скачает его сам в `bin/mediamtx` (Linux/macOS/Windows, x64/arm64). Ручной вариант — `npm run fetch:mediamtx`.

## Быстрый старт

```bash
# 1. Клонировать репозиторий
git clone <URL-репозитория> tapo-wall
cd tapo-wall

# 2. Установить зависимости: они лежат в двух пакетах — server/ и web/
#    (в корне зависимостей нет, поэтому корневой npm install не нужен)
#    Шаг обязателен: npm start собирает фронтенд сам, но зависимости не ставит.
npm --prefix server install
npm --prefix web install

# 3. Запустить: MediaMTX + сервер одной командой
npm start
```

Затем откройте **<http://localhost:3000>** и настройте стен из интерфейса — файл конфига руками править не нужно:

1. **«Добавить камеру»** → заполните `host`, `port`, `username`, `password` и пути потоков (`streams.hd` = `/stream1`, `streams.preview` = `/stream2`) → **«Сохранить»**. Запись уходит в `config/cameras.json`, а MediaMTX перезапускается автоматически, чтобы подхватить новый источник.
2. **Переключатель «Раскладка»** → двигайте плитки мышью, растягивайте за углы, поворачивайте за верхнюю точку, масштабируйте. Кнопка **«Прибрать»** раскладывает все камеры ровной сеткой, если раскладка «поехала».
3. **Опционально: «Настройки → Защита»** → задайте токен доступа, если хотите запретить редактирование без пароля (см. ниже).

### Свободная раскладка

Каждая камера хранит собственный `layout` — `{ x, y, w, h, rotation, scale }`:

- **двигать** — перетащите плитку целиком;
- **растягивать** — потяните за угол (минимальный размер 160×90);
- **поворачивать** — потяните за точку сверху плитки (угол нормализуется в 0…359°);
- **масштабировать** — поле `scale` (допустимо 0.25…4) масштабирует плитку вместе с содержимым, не меняя `w`/`h`;
- **«Прибрать»** — авто-раскладка по сетке.

Пустое поле `layout` означает `{ x: 0, y: 0, w: 320, h: 180, rotation: 0, scale: 1 }`. Если раскладка не нужна, оставьте значения по умолчанию — «Прибрать» всё равно приведёт стен в порядок.

### Опциональный токен доступа

По умолчанию API открыт: любой, кто видит `http://localhost:3000`, может смотреть и редактировать. В **«Настройки → Защита»** можно задать токен — тогда запросы на изменение конфига обязаны нести заголовок `x-tapo-token`. Это защита от случайных правок в общей сети, а **не** полноценная аутентификация: просмотр камер и сам UI остаются открытыми. Токен снимается там же (очистите поле). В файле конфига ему соответствует корневое поле `auth.token`.

Альтернатива `npm start`: скрипты-обёртки в корне — `./start.sh` (macOS/Linux) и `start.ps1` (Windows); оба просто вызывают `node scripts/start.mjs`.

Что именно делает `npm start` (`scripts/start.mjs`, чистый Node ESM без зависимостей):

1. **MediaMTX** — проверяет `bin/mediamtx`; если файла нет, запускает `scripts/fetch-mediamtx.mjs` и скачивает релиз под вашу ОС/архитектуру. Если скачать не удалось — печатает ручную инструкцию и выходит с ошибкой.
2. **Фронтенд** — проверяет `web/dist/index.html`; если сборки нет, выполняет `npm --prefix web run build`.
3. **Сервер** — запускает `npm --prefix server run start` и пробрасывает ему Ctrl-C (`SIGINT`/`SIGTERM`/`SIGHUP`).

Переменные окружения запуска:

| Переменная | Действие |
| --- | --- |
| `PORT` | Порт веб-интерфейса и API (по умолчанию `3000`). |
| `SKIP_FETCH_MEDIAMTX=1` | Никогда не скачивать MediaMTX, только сообщить о проблеме. |
| `SKIP_WEB_BUILD=1` | Никогда не собирать фронтенд автоматически. |
| `FORCE_WEB_BUILD=1` | Пересобрать фронтенд даже при наличии `web/dist`. |
| `MEDIAMTX_DISABLE=1` | Не запускать MediaMTX (сервер и UI поднимутся, видео не будет). |
| `MEDIAMTX_BIN` | Путь к собственному бинарнику MediaMTX вместо `bin/mediamtx`. |

Полезные команды:

```bash
npm run build:web        # пересобрать UI в web/dist
npm run fetch:mediamtx   # скачать/обновить bin/mediamtx
npm test                 # vitest в server/
npm --prefix server run dev   # сервер в watch-режиме через tsx
```

## Конфигурация

**Основной способ настройки — веб-интерфейс:** `http://localhost:3000` → «Настройки» → «Добавить камеру» / «Раскладка» / «Защита». Он пишет тот же `config/cameras.json`, поэтому ничего не нужно редактировать вручную и перезапускать сервер.

Файл `config/cameras.json` — **опциональный, advanced-способ**: он остаётся для массовой настройки, ручных правок, переноса стена на другую машину и бэкапа. Правьте его, только если так удобнее (например, залить сразу двадцать камер) или если UI недоступен. Полное описание всех полей с типами и значениями по умолчанию — в **[docs/config-reference.md](docs/config-reference.md)**.

Ключевые поля `config/cameras.json` (файл не коммитится — в репозитории только `config/cameras.example.json`):

| Поле | По умолчанию | Описание |
| --- | --- | --- |
| `httpPort` | `3000` | Порт веб-интерфейса по умолчанию. Переменная окружения `PORT` имеет приоритет над этим полем. |
| `mediamtx.hlsAddress` | `":8888"` | Адрес, на котором MediaMTX слушает HLS. Именно этот порт использует браузер. |
| `mediamtx.apiAddress` | `":9997"` | Адрес HTTP API MediaMTX. Через него сервер получает статусы онлайн/офлайн; в браузер не отдаётся. |
| `mediamtx.webrtcAddress` | `":8889"` | Адрес WebRTC/WHEP MediaMTX (необязательно; по умолчанию `:8889`). |
| `auth.token` | — (нет) | Токен доступа для редактирования. Пока поле пустое, API открыт; с токеном запросы на изменение конфига должны нести заголовок `x-tapo-token`. В UI задаётся в «Настройки → Защита». |
| `cameras[].id` | — | Уникальный идентификатор (латиница и дефисы). Попадает в URL-ы и в имена путей MediaMTX (`office-front_hd`), поэтому после настройки его лучше не менять. |
| `cameras[].name` | — | Подпись плитки в UI; можно кириллицей. |
| `cameras[].host` | — | IP-адрес камеры в локальной сети. |
| `cameras[].port` | — (обязательно) | Порт RTSP (число). У Tapo — `554`. |
| `cameras[].username` / `password` | — | Логин и пароль RTSP-аккаунта. **Никогда не покидают сервер.** |
| `cameras[].streams.hd` | — (обязательно) | Основной поток (высокое качество) для полноэкранного просмотра; у Tapo — `/stream1`. |
| `cameras[].streams.preview` | — (обязательно) | Поток превью (низкий битрейт) для плиток сетки; у Tapo — `/stream2`. |
| `cameras[].layout` | `{x:0,y:0,w:320,h:180,rotation:0,scale:1}` | Положение плитки на свободном холсте. Обычно задаётся перетаскиванием в режиме «Раскладка», поэтому трогать вручную его стоит только для сценариев массовой настройки. |

## Tapo + Keenetic

1. **Включите «Camera Account» в приложении Tapo.** Откройте приложение Tapo → выберите камеру → **Настройки** (шестерёнка) → **Дополнительно** → **Camera Account** (в некоторых версиях: «Учётная запись камеры» / «Дополнительные настройки»). Задайте логин и пароль и сохраните.

   Это **не** ваш аккаунт TP-Link из приложения: для RTSP/ONVIF создаётся отдельная учётная запись. Без неё камера не пустит по RTSP. Именно эти логин и пароль идут в поля `username`/`password`.
2. **Назначьте камерам статические IP на Keenetic.** Веб-интерфейс роутера → **Список устройств** (зарегистрированные устройства) → выберите камеру → **Зарегистрировать** / «Постоянный (статический) IP-адрес». Так адреса не поедут после перезагрузки DHCP, и конфиг не придётся править. Эти адреса идут в `host`.
3. **Потоки и порт.** RTSP работает на порту **554**; у камер Tapo доступны два потока:
   - `/stream1` — основной, HD-качество → `streams.hd`;
   - `/stream2` — превью, ниже разрешение и битрейт → `streams.preview`.

   Полный адрес получается такой: `rtsp://ЛОГИН:ПАРОЛЬ@192.168.1.101:554/stream1`.
4. **Проверьте поток до запуска видеостена** (подставьте свои значения):

   ```bash
   ffplay -rtsp_transport tcp "rtsp://tapo:ПАРОЛЬ@192.168.1.101:554/stream1"
   ```

   Если видео пошло в `ffplay`/VLC — запускайте `npm start` и добавляйте камеру в интерфейсе («Добавить камеру»), подставив тот же логин, пароль и адрес.

## FAQ и ограничения

- **Работает только из локальной сети.** Ничего не публикуется наружу, и по умолчанию аутентификации нет: `http://localhost:3000` увидит любой, кто в вашей сети. Токен из «Настройки → Защита» закрывает только *редактирование* конфига, просмотр и сам UI остаются открытыми. Не выставляйте порт в интернет — для удалённого доступа нужен VPN (см. Roadmap).
- **HLS даёт задержку 2–5 секунд.** Это цена дешёвого и совместимого протокола. Для мгновенной реакции нужен WebRTC (см. Roadmap); сейчас WebRTC-эндпоинт присутствует в API, но UI играет HLS.
- **Компьютер должен быть включён.** Пока машина спит или выключена — нет ни просмотра, ни MediaMTX. Это локальный стен, а не сервис.
- **Камера не отвечает?** Проверьте RTSP через `ffplay`, статический IP на Keenetic и статус бейджа (офлайн/подключение). Сервер продолжает работать даже при полностью недоступных камерах.
- **Порт занят.** `EADDRINUSE` на `:3000` — задайте другой через `PORT`. Порты `8888`/`9997` меняются в «Настройки» либо вручную в `config/cameras.json` (`mediamtx.hlsAddress` / `mediamtx.apiAddress`), после чего сервер нужно перезапустить.
- **Не коммитьте `config/cameras.json`** и не публикуйте скриншоты с ним: файл в `.gitignore` не случайно, в нём пароли RTSP.
- **Кириллица в `name`** поддерживается, а `id` держите латиницей — он уходит в URL.

## Roadmap

- [ ] **Telegram-алерты** — бот через `@BotFather`, watchdog «камера офлайн/онлайн», команда `/status`; работает локально, интернет нужен только для отправки.
- [ ] **WebRTC (низкая задержка)** — переключить плеер с HLS на WHEP: задержка падает до долей секунды, MediaMTX уже умеет WebRTC.
- [ ] **WireGuard / VPN мульти-сайт** — туннель между сайтами (например, на Keenetic): те же камеры, но из другой сети, без переписывания сервера.
- [ ] **24/7 на VPS** — перенос центра на VPS или домашний сервер, чтобы стен работал без включённого Mac.
- [ ] **Записи** — архив по движению (серверный детект, Frigate/FFmpeg), просмотр прошлых суток.
